# PAN Parrot roadmap

Prioritized backlog for making PAN Parrot the tool an XSOAR or XSIAM content developer reaches for. Each pull request updates the status column.

Status: **done**, **in progress**, **todo**.

## Defaults chosen without waiting

- Fetch simulation reveals one time window per poll, starting after the `since` or `first_fetch` query value. The default window is 5 minutes and the default batch is 3 records. Replaying the same `since` returns an empty page when dedup is on.
- Saved records and sequences are off until the Flow tab turns them on, so existing mocks stay stateless.
- A sequence step replaces the status and, when the body box is filled in, the body. After the last step, that last response repeats. Looping is stored on the spec but not exposed in the first version of the form.
- Request rules are exact. JSONPath is `$.a.b` and `$.items[0].id` only (no filters, wildcards, or scripts). XPath is `/a/b`, `/a/@attr`, and `//name` (no predicates). A blank header value means the header only has to be present. A blank body value means the path only has to exist. Priority defaults to 0, and an operation that has a query, header, or body rule beats an unconstrained operation on the same path. If every candidate has a rule and none match, the catch URL stays 404, which is how PAN-OS `type=` and `cmd=` rules already behave. SOAPAction and the SOAP request element stay score bonuses, not hard filters. A body that contains a DTD does not match a rule, and the catch route still rejects that body with 400 before routing.
- A recording is one https request on port 443. Private, loopback, and link-local addresses are rejected, and each redirect is checked again. A redirect to a different host does not receive credential headers. Header values and the request body are cleared in the form when Record is clicked, and they are not written to the mock or the request log.
- Outbound push sends one JSON object per event, up to three events when you click Push now, with at most two retries on a 5xx or a network error. The published-site job runs every 15 minutes, sends one event, allows one retry, and handles at most three mocks per run. Redirects are not followed. The signing secret is encrypted with the same AES-GCM key as dummy mock credentials and is not returned to the browser after it is saved. A blank secret on the next save keeps the stored one. The delivery log stores status and a short error, not the response body or the URL.
- Recorded field names containing token, secret, password, credential, email, or phone are replaced, along with emails, US phone numbers, SSNs, JWTs, AWS access key ids, and PEM private keys. The stored step is at most 8 KB and the sequence holds 12 steps. A recorded 404 stays 404. The operation's content type is unchanged. The sequence replaces the response while it is on, including when saved records are also on. Save the mock to keep the step.
- A personal token is `pp_` plus 32 random bytes, shown once, and stored as a SHA-256 hash. At most 5 active tokens. The browser session mints and revokes them. A token cannot mint another token. `npm run parrot -- login` writes `~/.config/pan-parrot/credentials.json` mode 0600 and does not print the token again.
- An integration YAML becomes at most 12 operations. The path is `/command-name` unless the description contains `METHOD /path`. Commands without outputs echo argument names. Fidelity is shape. The pytest export is offline `requests_mock` plus `test_data.json`. Dummy auth secrets are not copied into the export. Fixture bodies are capped at 8 KB.
- SigV4 checks the header form only, with a 15 minute clock window, and the credential's region and service must match the mock. Digest uses MD5 and a stateless nonce that lasts 10 minutes. JWT is HS256 only; `alg: none` and asymmetric algorithms are rejected; `exp` is required. WS-Security accepts PasswordText or PasswordDigest. NTLM verifies an NTLMv2 response against a challenge derived from the dummy password, because a Netlify function cannot pin the TCP connection between Type 2 and Type 3. Mutual TLS is not offered.
- A normal mock page stays at 2 MB. Opt-in NDJSON streams and file downloads stop at 6 MB, which is Netlify's buffered response limit. Netlify's streamed ceiling is 20 MB and the function timeout is 60 seconds. Slow drip pauses at most eight times, 200 ms apart, then sends the rest. Partial responses keep the first 40 percent of the body. Range supports one `bytes=` interval on a file download and is ignored for a live stream. Multiple ranges are rejected with 416.
- Sharing is by @paloaltonetworks.com address, at most 20 people, view or edit. The owner is the only one who can share, publish, or delete. A published mock can be opened read-only and cloned by anyone signed in. The catch URL stays open, the same as before. History keeps 15 specs. Audit keeps 400 events. Purge deletes captured calls and runtime, not the mock. Dark mode is not in this pass.
- `GET /api/health` and `GET /api/ping` are the same database check. They stay unauthenticated and do not report whether Resend is configured. That line is on Admin → Signals. The smoke script is `npm run smoke -- https://<site>`. A personal token is optional and only used to create, call, and delete one mock.
- Git history is not rewritten. The committed secrets were starter defaults (`your-super-secret-session-key-here`, `admin2024!`, a local Postgres password, and a Builder.io public key). Live `SESSION_SECRET` and `RESEND_API_KEY` belong only in the Netlify production environment.
- Captured calls expire after 14 days and 200 per mock. There is no backup service. Export a mock before deleting the Netlify project if you still want it.
- Request JSON is still capped before Zod parses it (96 KB for API bodies, 512 KB for a spec). Zod is 4.6.7 or newer so GHSA-mrhx-c7xc-m3w5 is not in the production tree. `z.record` takes a key schema and a value schema.
- 36 presets are verified, including QRadar v3, Elasticsearch v2, Gmail, EWS v2, Strata Logging Service, GuardDuty, Security Hub, Tenable, InsightIDR, SentinelOne v2, Carbon Black Endpoint Standard v3, Prisma Cloud v2, Entra ID users, Entra ID Protection, and Qualys VMDR. Cortex XDR also mocks alerts and endpoints. Defender XDR also mocks advanced hunting. The doc-check record is source.verification with status, docUrl, checkedAt, and differences.
- Content-pack export writes `test_data/<command>.json` as the raw HTTP body, which is what most XSOAR unit tests load, plus a README with `util_load_json` and the `mock_response` wrapper. Captured-call export uses the stored response preview, capped at 2000 characters, and does not include request headers. The shape diff walks the preset field tree against the first array element, or the array inside an OData or wrapped envelope. Optional fields that are absent are not called missing. The zip holds at most 19 body files plus the README.
- OAuth2 client-credentials responses include `expires_in`. Generic and Microsoft shapes also return a `refresh_token` that lasts 24 hours. `grant_type=refresh_token` issues a new pair. The previous refresh token keeps working until that 24 hours ends, because the check is stateless. CrowdStrike does not get a refresh token. An expired access token on a later call is `401` with `invalid_token`. Other grant types are `400 unsupported_grant_type`.
- Pagination is per operation. Offset/limit, page number, cursor/next token, and Link `rel=next` walk the virtual catalog (`totalRecords`, up to 20,000). Akamai style is NDJSON with a last-line `{ total, offset, limit }`, and a `from` time ignores `offset`. The studio Pagination control switches the envelope to match. Fetch backoff is off until enabled. When it is on, each authenticated data call counts in a window (default 5 calls, 60 seconds, Retry-After 2). Call N+1 is `429` with `Retry-After` and `X-RateLimit-Limit`, `X-RateLimit-Remaining`, and `X-RateLimit-Reset` (unix seconds when the window ends). Successful calls send the same X-RateLimit headers. The 429 counts, so the window stays full until it rolls. Token issuance does not count. The random chaos 429 is unchanged.
- An XSOAR instance helper is shown for presets and for mocks imported from integration YAML. Server URL is the catch URL. Dummy secrets are placed in the YAML's own parameter names. Trust any certificate is on, Use system proxy is off, and Fetch incidents is off until a manual command works. The downloadable JSON uses `data: [{ name, value }]`, with type 9 credentials as `{ identifier, password, vaultInstanceId }`. Integrations that append `:port/api/` (Panorama) are called out on the port row because that client drops the `/catch` path.
- The home page is written for a content developer. On a mock, Chaos and load test, Auth, Flow, Push, Export fixtures, and Share jump to that part of the page. Virtual records is the catalog size. One response still stops at 500. Playwright runs `e2e/journey.spec.ts` against `npm run dev` in CI, with Postgres and `AUTH_DEV_EXPOSE_CODE` only in that job.

## Next ideas

Things a content developer would still have to work around:

- 36 presets are checked against a public vendor reference. The rest of the catalog is still a guessed shape.
- A diff on the version list, so revert shows what would change.
- A way to close a catch URL (a second token or an IP allowlist). Today every catch URL is public and the rate limits are the only brake.
- An email to the owner when a catch URL receives its first call. Resend is already the mail path.
- One download of every mock you own that imports back into the studio. Pytest export is a test fixture, not a backup.
- XSIAM dataset and correlation samples, in addition to XSOAR integration packs.
- Dark mode.
- Richer JSONPath and XPath in the Match tab. The current subset is documented in the defaults above.
- Playwright against a Netlify preview. CI already runs the journey against the local dev server. A preview run would need a Netlify token in GitHub.
